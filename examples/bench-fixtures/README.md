# MD vs. Mdport benchmark fixtures

These generated fixtures compare CROP over Markdown source files with CROP over
equivalent `mdport.v1` transfer files at several corpus sizes.

```powershell
.\examples\bench-fixtures\generate.ps1 -Size all -Force
.\examples\bench-fixtures\run.ps1 -Size all -Runs 5
```

Sizes:

| Size | Documents | Purpose |
|------|----------:|---------|
| `small` | 8 | Smoke test and schema sanity check. |
| `medium` | 64 | Local development comparison. |
| `large` | 256 | Enough files to see ingest/packing trends without a large repo checkout. |

The generated output lives under `examples\bench-fixtures\out\` and is ignored by
git. Each size contains:

- `md\`: Markdown files with frontmatter, headings, paragraphs, and local links.
- `mdport\`: one compact `mdport.v1` JSON file per source, with AI-oriented
  context/provenance sections and refs. Mdport fixtures intentionally avoid
  frontmatter-as-evidence chunks so they measure the intended transfer shape, not
  a lossless Markdown paragraph clone.
- `manifest.json`: task, budget, document count, and root paths used by the run
  script.

`run.ps1` prints JSON summary rows with source/unit/edge counts, selected tokens,
quality score, average stage timings, and generated bytes for each mode.

## Quality goal

For these synthetic fixtures, Mdport should beat Markdown by at least `+0.10`
quality score at medium and large sizes while running in no more than 70% of the
Markdown total time. That target reflects the expected Mdport advantage: fewer
cleaner evidence units with preserved provenance, not merely smaller bytes.
