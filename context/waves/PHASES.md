# MDCROP Wave Phases

## Active wave

`2026-10-31-wasm-boundary` — qualify a bounded public fixture and portable
selection boundary before implementing a browser experience. Pulse 01 is the
scope/compile decision; Pulse 02 remains proposed.

## Completed waves

`2026-05-16-mdcrop-status-contracts` - hardened corpus status output into
consumer contracts with `mdcrop.corpus-status.v1`, policy-aware strict gates,
root/view goldens, and downstream documentation.

`2026-05-15-mdcrop-view-inspection` - added safe preflight inspection for named
views, store-wide inspection, strict CI gates, Markdown side-info surfaces, and
combined corpus status pages for roots and views.

`2026-05-15-mdcrop-named-views` - turned ad hoc mdcrop recipes into persisted named
views for reusable context packs, benchmarks, prefix-cache workflows, and
large-corpus filtered/searchable views.

`2026-05-15-mdcrop-real-corpus-benchmarks` - moved from deterministic fixtures to
local-corpus benchmark commands, manifests, competitor exports, aggregate
reports, and fair benchmark documentation.

`2026-05-15-mdcrop-evaluation-suite` - built the apple-to-apple fixture and
baseline suite, metrics contract, and offline competitor import contract that
prove when graph-cut context mdcropping beats ordinary ranking/index approaches.

`2026-05-15-mdcrop-product` - established the local-first MDCROP engine and product
surface for graph-cut context mdcropping.

## Operating protocol

1. Keep waves small enough to finish with tests and a commit.
2. Every pulse must define scout commands, implementation tasks, documentation
   updates, and validation gates.
3. New graph behavior needs a positive fixture and at least one negative input
   test.
4. Dependencies on BISECT shared kernels must work through GitHub and through
   the local peer override documented in `.cargo/config.local.example.toml`.
